| D39 | **Vercel production returns HTTP 500 (with `x-matched-path: /500`) for missing article/lesson slugs in valid corpora** — `https://nxhhuy.tech/en/blog/<corpus>/<missing-slug>` returns 500 instead of 404. Local `pnpm dev` returns 404 (dev skips `'use cache'`), `pnpm build && pnpm start` reproduces the 500, Vercel prod reproduces the 500. Root cause: under `cacheComponents: true` + PPR, Next.js generates an empty `[slug].html` fallback (0 bytes, `status: 200`) for URLs whose `(corpus, slug)` pair isn't in `generateStaticParams()`. The page handler is NEVER invoked for static fallback URLs — Vercel's edge serves the empty shell, which the response transformer turns into `/500`. The bad-corpus case (e.g. `/en/blog/bogus/foo`) works in both dev and prod because no `generateStaticParams` entry exists for that corpus, so the page handler IS invoked and the per-segment `not-found.tsx` renders correctly. `dynamicParams = false` is forbidden under Cache Components (`Route segment config "dynamicParams" is not compatible with nextConfig.cacheComponents`); `dynamic = 'force-dynamic'` is also forbidden. PR #56 added per-segment `not-found.tsx` files which fix the bad-corpus case but NOT the missing-article case (page handler doesn't run for static fallback URLs). Fix landed in PR #63 (segment-level + app-wide `not-found.tsx` + `generateMetadata`-notFound) and **closed by PR #65 (commit `d332b3a`, 2026-08-28) — middleware at the edge**: scripts/build-slug-allowlist.mjs reads catalog.json and writes `apps/web/slug-allowlist.json` (196 article slugs) + `apps/web/lesson-allowlist.json` (18 lesson slugs); `apps/web/middleware.ts` imports those JSON files (Next.js inlines static imports into the middleware bundle, no runtime file I/O), matches the route patterns, and returns a real 404 response for invalid combinations. Middleware runs BEFORE Next.js's static routing, so it bypasses the empty `[slug].html` fallback shell entirely. Verified in prod: `curl https://nxhhuy.tech/en/blog/react/hooks` returns 404 (was 500); missing lesson URLs also return 404.
